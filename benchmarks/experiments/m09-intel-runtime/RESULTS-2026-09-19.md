The new runtime completed both frozen coding tasks normally in 41:38, versus 42:47 for the recorded production control. ## Quality and integrity

- Both runs passed all 9/9 independent held-out acceptance cases: initial setup and permissions; preservation of non-auth settings/comments during credential rotation; explicit host changes; password-only rotation; unchanged files after cancellation/mismatch; malformed/duplicate input rejection; and distinct disabled/unreachable runner states.
- Candidate workspace checks: 565 tests passed, 6 intentionally skipped host-only nested sandbox tests, all four package builds passed, typecheck passed, lint passed. The reference had 570 passing tests and the same 6 skips. Test totals differ because the agents wrote different additional tests; the candidate did not remove existing tests to pass.
- Formatting failed only on the same seven pre-existing unrelated files, explicitly excluded from cleanup by the frozen task. No new formatting failures.
- Reviewed changed CLI, contracts, backend status handling, frontend messaging and the new CLI tests. Rotation preserves untouched configuration lines; writes retain unique exclusive temporary files, restrictive permissions and atomic rename. Existing secrets are excluded from new diagnostics. The runner status field is optional, and English/German messages distinguish an unavailable configured runner from disabled execution.
- The untracked new CLI regression test was included in review and in the evaluator run; ordinary result.diff alone does not include it. review-file-inventory.json in the run records all 13 changed/new files and their hashes.
- The original harness hash set still matches. Candidate model accounting: 119/119 valid requests, no failure category, no compaction, both initial and follow-up complete, zero coding-phase preemptions.
- Before coding, the full-context probe processed 200448 input tokens and returned all four expected markers (200 output tokens), preserving the configured 200704-token ceiling. Prefix correctness, MTP acceptance and isolated tool/continuation probes passed.
- The four video-processor documentation errors in startup logs are also present in the baseline. No engine crash, OOM or traceback was found in the candidate log.
- This demonstrates the same measured task quality on this workload. It is not a general model-quality evaluation or an exhaustive security/code audit. No additional full test rerun was necessary after reviewing the unchanged independently evaluated output.

## Conclusion

A modest positive result for the completed coding session, with no detected quality regression in the measured checks. Prefill is effectively unchanged across comparable contexts; decode is somewhat higher overall but not uniformly better in every band. Different adaptive trajectories and MTP acceptance prevent attribution of the entire gain to the runtime. An identical-request replay would be needed to isolate a small runtime-only speedup more convincingly. The new image remains an evaluated candidate; production has not been promoted.
