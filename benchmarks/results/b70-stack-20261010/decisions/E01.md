# E01 — stable oneDNN maintenance candidate

**MAINTENANCE_SURVIVOR — selected for production promotion; no speedup claim.**

The relevant maintenance change moves SDPA `S_max` initialization before the
query-arrival barrier. The qualified old source `0e2a5bfe` and its loaded
binary were audited as lacking this ordering fix. Stable 3.13.4 at
`c531fe1a` contains upstream `b38b47c9`. This establishes a relevant code
change, not a reproduced failure in the existing serving specialization.

Builds retain the original GPU-SYCL/Graph/CPU-NONE options and pinned
compiler. EXL3 source `fc8f8c9f` is rebuilt against the matching oneDNN headers
and library; M04 and the vLLM/Torch/Triton/runtime profile remain unchanged.
The frozen candidate image is `36e41ea0`, metadata-only above tested runtime
parent `b772d379`, with identical RootFS. Exact artifact hashes and commands
are in the [build receipts](../E01-build-public-receipts.json) and
[final assessment](../assessment.json).

Independent operator, graph/live-buffer, difficult FP16 input, real-weight
and bounded in-flight cache tests pass their original tolerances. The exact
short-path array comparison **failed and remains failed**. A separately
hashed [numerical review](../E01-numerical-review.json) accepts the finite
quality/reference results; this is neither bit identity nor a general
accuracy improvement. BF16 reference evaluation is on CPU; target and MTP
runtime tensors remain FP16 without a BF16 bridge.

The [memory ledger](../E01-memory-ledger.json) records an actual
261,120-input + 1,024-output request and unchanged matched KV pools. The
metadata-frozen final image passes [operational gates](../operations.json),
including media, abort/prefix extension, concurrent prefill/decode, 16-way
admission pressure and restart. Original failures and their reviewed
contemporaneous C16 comparison remain published separately.

Eight independent core paired blocks plus five protected blocks yield no
performance survivor: weighted cold decode +0.111% (descriptive 95% interval
−0.701% to +0.893%), warm −0.752% (−1.865% to +0.236%). The warm prose-C4
client-throughput loss and its wide interval are retained in the
[paired report](../E01-confirmation-eight-blocks.json).

The complete frozen final matrix is **70 waves / 124 requests**, plus three
isolated 64K prefix resends, with zero preemptions and zero excess recompute.
The [historical comparison](../benchmark-comparison.json) flags 4K C1 decode
−4.707%, 32K C1 decode −3.199%, and 4K C4 median TTFT +6.356%. These are
historical median review triggers, not paired confidence intervals. Three
balanced fresh-worker pairs completed exactly those original fixtures,
retaining all original repeats and 1,024-output budgets. Paired per-fixture
native decode is +1.873% at 4K and +1.404% at 32K; C4 client rate is −0.923%
with empirical request E2E p95 +0.882%. The smaller consistent C4 loss is an
explicit maintenance tradeoff. No clear pre-registered threshold-exceeding
loss is confirmed, so the conditional ordering-fix-only fallback is not
required and remains unbuilt. Counter-window limitations and all adverse
results are retained in the [final review](../performance-review.json).

The qualified production image `194a8786` and saved v3 rollback configuration
remain the defaults until actual permanent-service promotion succeeds.
The [release decision](../decision.json) permits that separately verified
step. No universal noninferiority, accuracy gain or performance-survivor
claim follows from this finite maintenance qualification.
