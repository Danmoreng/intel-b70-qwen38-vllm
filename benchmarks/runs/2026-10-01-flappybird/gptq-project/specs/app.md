# app public API contract

Export mountApp(root,options={}) from src/app.js, safely importable in Node (no top-level DOM). Root is a DOM element. options {autoStart?:true}; autoStart false disables requestAnimationFrame for tests. Returns {start,step,flap,pause,resume,restart,getState,destroy}. Integrate simulation, renderer and input. Markup has exactly one canvas[data-testid="game-canvas"], button[data-testid="start"], button[data-testid="pause"], button[data-testid="restart"], element[data-testid="score"], element[data-testid="status"], element[data-testid="live"] with role=status and aria-live=polite. Buttons have accessible labels. Initial ready game; start() moves to running; flap() starts or flaps; step(count=1) advances count integer0..10000 ticks while running and renders/updates UI; pause/resume preserve state; restart resets same config to ready. getState returns detached snapshots. Keyboard Space/ArrowUp flap, KeyP toggles pause, KeyR restart; pointerdown canvas flaps; ignore repeated held keydowns. Ignore keyboard while input/textarea focused. Visibility hidden pauses. Responsive canvas resize, DPR capped<=4. destroy removes all listeners, cancels rAF, destroys renderer and is idempotent. Subsequent commands except getState throw. index.html loads main.js module calling mountApp on #app; CSS supports mobile layout, keyboard focus and reduced motion. No third-party libraries, replay, level editor, campaign or backend. Add a short USER_GUIDE.md with controls, deterministic seed and static-server instructions. The objective is a small working game.


# Settings and scores extension (final stage)

Add labelled number inputs with data-testid settings-seed, settings-gravity and settings-gap, plus settings-apply button and settings-error region. Initial values match current game config. Applying valid values uses validateConfig, updates only seed/gravity/gapHeight, restarts ready and updates the detached getState snapshot. Invalid values preserve all game config/state and display a nonempty accessible error message. Keyboard game shortcuts do not act while editing fields. Add a labelled player-name input (default Player), trim names using the scores contract, and save exactly one score when each running game first transitions to gameover. Render persisted entries as data-testid score-row elements showing name and score. Add scores-clear button. Browser localStorage uses key flappybird.scores.v1; it persists through reloads. After destroy/re-mount the saved list is displayed. Repeated step calls after gameover do not duplicate entries. Applying settings must retain the score list. Keep all previous controls, lifecycle, physics, accessibility and real-entry requirements. No level editor, replay, network, framework or third-party runtime dependency. Document settings, score persistence and clearing in USER_GUIDE.md.
